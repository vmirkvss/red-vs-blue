# Отчёт о проверке

Дата: 31 октября 2026 года (Asia/Almaty).
Среда: macOS, Node.js 22.23.3, Java 21, Firebase RTDB emulator, Vitest 5.0.5.

| Проверка | Результат |
| --- | --- |
| Установка зависимостей | Успешно, package-lock.json включён |
| `npm run build` | TypeScript и Vite production build успешно |
| `npm test` | 4 теста успешно |
| `npm run test:rules` | 13 тестов успешно |
| `npm run test:load` | 1 тест: 60 независимых SDK-клиентов успешно |
| `npm audit --omit=dev` | 0 известных уязвимостей |
| `npm audit` | 5 moderate в цепочках dev-only Firebase CLI; 0 high/critical |

## Что проверено в emulator

- Неавторизованный доступ; изменение участником вопросов, состояния, tally и allowlist.
- Аккаунт с email, но без admin UID, не управляет игрой.
- Один неизменяемый голос, запрет удаления, подмены UID и неправильного значения.
- Гонка двух транзакций одного UID: только одна создаёт голос.
- Закрытый/устаревший раунд отклоняет голос.
- До раскрытия чужие голоса недоступны; после раскрытия виден текущий раунд.
- Профили участников и присутствие ограничены собственным UID.
- Reconnect восстанавливает актуальный вопрос, а повторный вход с тем же UID — прежний голос.
- Атомарный reset очищает голоса и блокирует старый раунд.
- Редактирование сценария разрешено ведущему только в ожидании.
- 60 клиентов одновременно регистрируются, отмечают присутствие, подписываются на состояние и голосуют: получено 24 красных / 36 синих, 40% / 60%. Все 60 получают раскрытие и одинаковый итог. При отключении клиента запись присутствия удаляется сервером.

Предупреждения `permission_denied` в логах отрицательных тестов ожидаемы: это подтверждение отказа правил, а не падение тестов.

## Browser smoke test

В браузере с реальными локальными Auth и RTDB emulators (без production-данных) выполнено:

1. Вход тестового email/password администратора из allowlist.
2. Создание игры и запись трёх стартовых вопросов в RTDB.
3. Подключение независимой анонимной сессии участника на другом origin, ввод ника, появление регистрации и присутствия в пульте.
4. Открытие вопроса из пульта; участник и проектор автоматически отображают его.
5. Принятие голоса, блокировка кнопок, перезагрузка участника: голос и UID сохранены.
6. Закрытие и раскрытие: пульт, участник и проектор показывают одинаковый результат.
7. Следующий вопрос: предыдущий голос не блокирует новый раунд; второй голос и раскрытие проходят успешно.
8. Визуальная проверка проектора при 1280×720: вопрос, ответы, результат и присутствие помещаются на экране для проверенных вопросов.

Тестовые учётные записи и данные существовали только в emulator. Серверы остановлены, временная `.env.local` удалена. Снимок экрана рядом с архивом показывает реальный тестовый раунд с одним принятым голосом, а не подставленные результаты.

## Зависимости

Обновлены Firebase CLI и Vitest; добавлен совместимый override `@grpc/grpc-js >=1.13.6` для устранения high advisory в транзитивной зависимости Firebase. Production audit чистый. Остались moderate advisories в dev-only цепочках `@opentelemetry/core → @google-cloud/pubsub → firebase-tools` и `uuid → gaxios → firebase-tools`. Они не включаются в браузерную сборку. Не применялся `npm audit fix --force`, который предлагал несовместимые откаты Firebase SDK/CLI. Перед последующими обновлениями повторите audit и тесты правил.

## Не проверено

- Настоящий Firebase-проект пользователя, production Auth и опубликованные правила.
- Публикация в GitHub Pages: репозиторий и конфигурация Firebase не предоставлены.
- 60 физических телефонов, Safari iOS / Chrome Android и Wi-Fi площадки.
- Реальные квоты Spark, задержки WAN, длительное фоновое выполнение на мобильных ОС.

Успешный тест 60 emulator-клиентов **не доказывает эксплуатационную надёжность 60 телефонов**. Перед мероприятием выполните ручную репетицию из README.
