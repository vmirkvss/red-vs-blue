# Проверка двухэтапного формата

Дата: 31 октября 2026 (Asia/Almaty). macOS, Node.js 22.23.3, Java 21, Firebase RTDB emulator, Vitest 5.0.5.

| Проверка | Результат |
|---|---|
| Production build / TypeScript | Пройдено |
| Unit tests | 8 пройдено |
| Security / integration tests | 28 пройдено |
| Load test | 60 независимых клиентов, 2 этапа, 1 тест пройден |
| Browser smoke test | Реальные локальные Auth + RTDB emulators, 3 интерфейса |

## Автоматические проверки

- Отдельное хранение мнений и прогнозов; повторные и одновременные дубликаты отклоняются.
- Неверный UID, значение, закрытый этап и старый roundId отклоняются.
- Голос без счётчика, неверный счётчик, изменение или удаление голоса запрещены.
- Скрыты чужие голоса, распределения и промежуточный рейтинг.
- Правила отклоняют пропуск этапа и изменение снимка вопроса даже от ведущего.
- Прогнозы сравниваются с большинством первого этапа; проверены +1/+0, ничья, ноль мнений, отсутствие прогноза и накопление за два вопроса.
- Запрещено повторно открыть уже сыгранный question ID.
- Нельзя пропустить участника при начислении, раскрыть неполный результат, подделать баллы или итоговые счётчики даже с UID ведущего.
- Подсчёт продолжается после частичной обработки. Повторная и конкурентная финализация не дублирует баллы.
- Регистрация атомарно дополняет неизменяемый список; нельзя удалить/исказить список чужим UID. Во время подсчёта регистрация закрыта; поздний вход после раскрытия не меняет прежний рейтинг.
- Reconnect/новая SDK-сессия с тем же UID восстанавливает этап и принятый голос.
- Сброс требует завершённой игры, очищает новый рейтинг/голоса и сохраняет участников/вопросы. Миграция сохраняет старые голоса отдельно, не придумывая очков.
- Пустая игра без участников может завершить вопрос с нулевым результатом; фиктивную строку рейтинга создать нельзя.

## Нагрузка

60 независимых SDK-клиентов одновременно регистрируются и подключают state/presence. Затем подают 38/22 мнения и 45/15 прогнозы. Все получают каждый переход, обе корректные сводки и рейтинг из 60 строк с 45 начисленными баллами. Проверено серверное удаление presence при disconnect.

Это локальная проверка emulator, а не проверка 60 реальных телефонов, production Auth, региональной задержки Firebase или Wi-Fi площадки.

## Проверка браузером

В независимых origin-сессиях ведущего и участника, с отдельной вкладкой проектора:

1. Вход ведущего и создание игры с сохранением примерных вопросов.
2. Регистрация участника и появление online-count.
3. Первый этап, принятый личный ответ и блокировка кнопок.
4. Второй этап на том же вопросе, новая инструкция, отсутствие раскрытия процентов.
5. Принятый прогноз и его сохранение после перезагрузки.
6. Закрытие этапа, серверно проверенное начисление +1, синхронное раскрытие обеих диаграмм и рейтинга на всех интерфейсах.
7. Отдельная вкладка рейтинга в пульте, финальная таблица с медалью, подтверждение перед сбросом.
8. Визуальная проверка проектора при 1280×720 для проверенного вопроса.

Скриншот `two-phase-preview.png` рядом с проектом показывает действительный локальный тестовый вопрос с одним участником; результаты не подставлены в production-приложение.

## Выпуск

Production Firebase и действующий GitHub Pages не переключались на v2: новые правила ещё нужно опубликовать из авторизованной Firebase Console/CLI. Изменения подготовлены в отдельной ветке; точный порядок — в MIGRATION.md. Конфигурация Firebase, allowlist и секреты не менялись.

Зависимости не менялись: прежний production audit был чистым; оставались 5 moderate advisories в dev-only цепочках Firebase CLI. Проверки безопасности игры используют реальные сгенерированные RTDB rules. Полный исходник выражений — `scripts/generate_rules.py`.
